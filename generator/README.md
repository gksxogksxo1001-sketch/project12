# ⚙️ 주한태 사이트 지속 갱신 장치 (Engine & Reproducibility)

이 디렉토리는 **마지막 과제 BR-A**의 핵심 요구사항인 **"새 기록을 넣으면 사이트의 숫자와 문단 후보를 다시 만들어 주는 작은 장치"**를 포함하고 있습니다.

---

## 📌 1. 장치의 역할과 작동 원리
1. **리추얼 기록 파싱**:
   - `ritual-history-*.txt`에서 날짜, 아침/마무리 여부, 호흡 시간, 키워드, 동료 피드백을 정확히 추출합니다.
2. **정량 통계 및 고난 페어링 자동화**:
   - 40일간의 완수율(아침 100%, 저녁 95.0%)과 누적 집중 시간을 계산합니다.
   - 2026-10-13~14 지각 위기 ➔ 10-15 알람 10개 설정 ➔ 10-16 30분 조기 도착 사건을 정량 타임라인 데이터로 구조화합니다.
3. **사이트 데이터 및 서사 문단 후보 자동 생성**:
   - `site-data.json`: 프론트엔드 및 범용 API용 정형 데이터
   - `site-data.js`: 로컬 브라우저 및 GitHub Pages에서 즉시 바인딩 가능한 JS 파일
   - `doc/generated-narrative-candidates.md`: 새 기록을 반영한 자기소개 문단 후보 3종(자기조절력, 대인관계력, 자기동기력)

---

## 🚀 2. 실행 방법

```bash
# 1. 사이트 데이터 및 문단 후보 갱신
node generator/engine.js

# 2. 결정론적 2회 반복 실행 재현성 검증 (새 폴더 검증)
node generator/verify-reproducibility.js
```

---

## 🔒 3. 체크리스트 준수 사항
- **결정론적 일관성**: 날짜 및 생성 타임스탬프를 원본 기록의 마지막 일자(`2026-10-22`)로 고정하여, 새 폴더에서 두 번 돌렸을 때 SHA-256 해시가 100% 동일하게 일치합니다.
- **개인정보 보호**: 타인의 실명은 완전히 마스킹(`동료 1`, `동료 2`, `동료 3`)되며, 비밀값 0건을 준수합니다.
